# kuku-practice

# 九九クエスト
 
小学校2年生向けの、ゲーム感覚で九九を練習できるWebアプリです。
 
九九の問題を解きながら冒険者とモンスターが戦い、正解すると冒険者がモンスターを攻撃、不正解または時間切れになるとモンスターから攻撃を受けます。
 
単純に正解数を競うだけではなく、
 
**「問題を解く → 結果を蓄積する → 苦手を発見する → 苦手問題を練習する」**
 
という学習サイクルを目的としています。
 
---
 
# 1. 技術構成
 
本アプリはサーバーを使用しない静的Webアプリとして構成します。
 
## 使用技術
 
- HTML
- CSS
- Vanilla JavaScript
- Browser LocalStorage
- GitHub Pages
 
フレームワークや外部ライブラリは使用していません。
 
## ファイル構成
 
```text
/
├── index.html
├── style.css
├── app.js
└── README.md
```
 
GitHub Pagesからそのまま公開できる構成とします。

# 2. 対象ユーザー
 
主な対象は、小学校2年生程度の九九を学習している子どもです。
 
そのためUIでは以下を重視します。
 
- 子どもが直感的に操作できること
- スマートフォンで操作しやすいこと
- 文字・数字・ボタンを十分大きくすること
- 操作手順をできるだけ少なくすること
- 日本語入力IMEを使用しないこと
- 間違えても学習意欲を失いにくい表現にすること
- 「最後までやればクリアできる」ゲーム設計にすること

# 5. 段別の出題方法
 
2〜9の段を選択した場合、次に出題方法を選択します。
 
## じゅんばん
 
選択した段について、
 
```text
×1
×2
×3
×4
×5
×6
×7
×8
×9
```
 
の順に出題します。
 
全9問です。
 
例：7の段
 
```text
7 × 1
7 × 2
7 × 3
...
7 × 9
```
 
## ランダム
 
選択した段から10問出題します。
 
最初の9問は可能な限り `×1〜×9` が重複しないようにシャッフルし、10問目をランダムに生成します。

# 6. 難易度
 
ゲーム開始前に以下の3段階から選択します。
 
| 難易度 | 1問の制限時間 | 冒険者ライフ |
|---|---:|---:|
| 🌱 やさしい | 15秒 | ❤️×5 |
| ⚔️ ふつう | 10秒 | ❤️×3 |
| 🔥 むずかしい | 5秒 | ❤️×2 |
 
## 重要
 
難易度によって九九問題そのものの難しさは変更しません。
 
難易度の差は原則として、
 
- 1問あたりの制限時間
- 冒険者の初期ライフ
 
のみで表現します。
 
つまり「むずかしい」を選択しても、問題内容そのものを複雑にする仕様にはしません。

# 8. 回答方法
 
スマートフォン標準IMEは使用しません。
 
HTMLの `<input>` を使用して端末のキーボードを表示する方式ではなく、アプリ内に専用テンキーを表示します。
 
## テンキー
 
```text
1  2  3
4  5  6
7  8  9
けす  0  けってい
```
 
## 入力仕様
 
- 最大2桁
- 九九の最大値81を想定
- 先頭の0は入力不可
- 「けす」で末尾1文字を削除
- 「けってい」で回答確定
- 回答確定後はテンキーを非表示
- 「つぎのもんだい」でテンキーを再表示
 
数字を1文字入力しただけでは自動判定しません。
 
例として答えが12の場合、`1` を押した段階で誤答判定されないようにするためです。
 
---
 
# 9. 制限時間
 
各問題には難易度に応じた制限時間を設定します。
 
## やさしい
 
15秒
 
## ふつう
 
10秒
 
## むずかしい
 
5秒
 
残り時間は、
 
- 秒数
- プログレスバー
 
の両方で表示します。
 
残り時間に応じてタイマーバーの色を変化させます。
 
- 通常：青
- 残り約60%以下：黄色系
- 残り約30%以下：赤
 
時間が0になると自動的に時間切れとして処理します。
 
---
 
# 10. 正解時の処理
 
正解した場合は、
 
1. 正解数を+1
2. 回答履歴へ正解として保存
3. 〇×履歴へ「〇」を追加
4. 学習履歴をLocalStorageへ保存
5. 冒険者の攻撃アニメーションを表示
6. モンスターへのダメージ演出を表示
7. モンスターHPを1減らす
 
正解メッセージはランダムで表示できます。
 
例：
 
- ⚔️ せいかい！ こうげき！
- 💥 クリティカル！
- ⭐ すごい！
- 🔥 ナイスこうげき！
- ✨ ばっちり！
 
---
 
# 11. 不正解時の処理
 
不正解の場合は、
 
1. 回答履歴へ不正解として保存
2. 〇×履歴へ「×」を追加
3. 間違えた問題として保持
4. 学習履歴をLocalStorageへ保存
5. モンスターの攻撃アニメーションを表示
6. 冒険者のダメージ演出を表示
7. 冒険者ライフを1減らす
8. 正しい答えを表示
9. 問題消化に伴いモンスターHPを1減らす
 
冒険者ライフは0未満にはしません。
 
---
 
# 12. 時間切れ
 
制限時間が0になった場合は不正解扱いとします。
 
表示例：
 
```text
⏰ じかんぎれ！ こたえは 42！
```
 
時間切れ時は、
 
- 不正解として学習履歴に保存
- 〇×履歴へ「×」
- 冒険者ライフ-1
- モンスター攻撃
- 正答を表示
 
とします。
 
学習履歴には `timeout: true` を保存します。
 
---
 
# 13. モンスターHP
 
本アプリでは、
 
**問題を最後まで解けば必ずモンスターを倒せる**
 
ことを重要なゲーム仕様とします。
 
そのためモンスターHPは正解数だけでは管理しません。
 
開始時：
 
```text
monsterMaxHp = 出題問題数
monsterHp = 出題問題数
```
 
1問終了するごとに、
 
```text
monsterHp - 1
```
 
とします。
 
例：9問の場合
 
```text
9 → 8 → 7 → 6 → 5 → 4 → 3 → 2 → 1 → 0
```
 
正解の場合は「冒険者が攻撃した結果HPが減った」ように演出します。
 
不正解の場合は「モンスターから攻撃を受けた後、その問題を突破した」という扱いでHPを減らします。
 
## この仕様を変更しない理由
 
九九をまだ覚えている途中の子どもでも、
 
**最後まで問題を解けばモンスターを倒せる**
 
ようにするためです。
 
誤答によって「どうやっても勝てない」状態にはしません。
 
---
 
# 14. 冒険者ライフ
 
ライフ数は難易度によって決まります。
 
不正解または時間切れになると、
 
```text
heroLife - 1
```
 
とします。
 
ただしライフが0になってもゲームオーバーにはしません。
 
```text
❤️❤️❤️
❤️❤️♡
❤️♡♡
♡♡♡
```
 
となっても問題は継続します。
 
## 重要
 
ライフは、
 
**正確に答えられたかをゲームとして表現するための指標**
 
です。
 
学習を途中で強制終了するための仕組みには使用しません。
 
---

```text

さいごまで がんばったね！
```

# 16. 〇×履歴
 
問題画面には現在のチャレンジの回答結果を表示します。
 
例：
 
```text
〇 〇 × 〇 ・ ・ ・ ・ ・
```
 
- 〇：正解
- ×：不正解または時間切れ
- ・：未回答
 
回答するたびにリアルタイムで更新します。

# 17. 間違い復習

```text
🔥 まちがえたもんだいに ちょうせん！
```
 
を表示します。
 
選択すると、そのチャレンジで間違えた問題だけを再出題します。
 
復習時も回答結果はLocalStorageへ保存します。

# 18. 学習履歴
 
すべての回答結果はBrowser LocalStorageへ保存します。
 
現在のStorage Key：
 
```text
kuku-study-history-v2
```
 
既存の学習データとの互換性維持のため、変更理由がない限りStorage Keyを変更しないでください。
 
保存データ例：
 
```json
{
  "a": 7,
  "b": 8,
  "answer": 56,
  "userAnswer": 54,
  "correct": false,
  "mode": "random",
  "difficulty": "normal",
  "timeout": false,
  "date": "2026-11-25T12:00:00.000Z"
}
```
 
時間切れの場合、`userAnswer` は `null` になることがあります。

# 23. 苦手問題モード

選択順位：
 
1. 正答率が低い問題
2. 正答率が同じ場合は挑戦回数が多い問題
 
未挑戦の問題は苦手問題として扱いません。

---
 
# 26. IMEを使用しない
 
回答欄はHTMLのテキスト入力フォームではありません。
 
表示専用要素とアプリ内テンキーを使用します。
 
そのため後続開発でも、特別な理由がない限り、
 
```html
<input type="text">
<input type="number">
```
 
を九九回答用として再導入しないでください。
 
スマートフォンでIMEが開閉することによる操作ストレスを避けるためです。

# 34. 開発方針
 
このアプリで最も重要なのは、
 
**九九を覚えることが「やらされる勉強」ではなく、モンスターを倒すための行動になること**
 
です。
 
一方でゲームが難しすぎて九九練習の邪魔にならないようにします。
 
そのため、
 
**学習 → バトル演出 → 達成感 → 苦手発見 → 再挑戦**
 
というサイクルを優先して開発します。
